# ЭнзиДекс — сайт продукта

Полные требования: `docs/REQUIREMENTS.md`. Прочитай их перед работой над любой задачей.
Правки заказчика и наполнение по отчёту: `docs/CORRECTIONS.md` — читай сразу после ТЗ,
иначе восстановишь то, что просили убрать, или разойдёшься с фактами из отчёта.
Пробелы в контенте фиксируй в `docs/CONTENT-GAPS.md`.

## Продукт

Стоматологический гель «ЭнзиДекс», 10 мл, на основе фермента декстраназы.
Разрушает полисахаридный матрикс зубной биоплёнки. Без фтора.
Изготовитель: ООО «ЭНЗИДЕКС», Пермский край, РФ.

## Стек

Next.js 16 (App Router), TypeScript strict, Tailwind CSS v4, статический экспорт (`output: 'export'`).
Без UI-китов. Иконки — локальные SVG в `components/icons`. Шрифт — Onest через `next/font/google`
(файлы скачиваются на этапе сборки и раздаются со своего домена; запроса к Google в рантайме нет).

## Страницы

`/` · `/product` · `/faq` · 404

Страниц «Научная база» и «Юридические данные» нет по решению заказчика.
Реквизиты изготовителя — в подвале (`components/layout/Footer.tsx`).

## Сайт информационный

Никаких активных операций: ни форм, ни заявок, ни сбора персональных данных,
ни аналитики. Это решение заказчика (см. `docs/CORRECTIONS.md`), а не
временное состояние. Не добавляй формы обратной связи, кнопки «оставить
заявку» и подобное без явной просьбы — вместе с ними вернутся требования
152-ФЗ, от которых сайт сейчас свободен.

## Жёсткие правила

1. Тексты живут в `/content/*.ts`, а не в JSX. Всегда.
2. Нет данных — ставь `TODO_CONTENT` и пиши строку в `docs/CONTENT-GAPS.md`.
   На сайте маркер выводится как «Требует корректировки» — так заказчик видит
   пробелы прямо на страницах. Подстановку делают `components/ui/Value` для
   целых полей и `RichText` для маркера внутри фразы.
   Не выдумывай факты о продукте, составе, исследованиях, реквизитах.
   Общеизвестную науку (что такое биоплёнка, что делает декстраназа, функция
   ингредиента по INCI) писать можно и нужно — это не выдумка, а справочный факт.
3. Никаких утверждений о лечебном действии. Лабораторные результаты помечаются
   как in vitro. Противокариесное и осветляющее действие — цели разработки,
   а не свойства продукта: клинических исследований не было, регуляторный
   статус не подтверждён. Названия конкурирующих брендов на сайт не выносим (BC-4).
4. Одна секция = один компонент. Больше ~150 строк — разбивай.
5. Цвета только через токены, не произвольные hex в классах.
6. Секреты — только в env, никогда в коде. Сейчас секретов нет вовсе.
7. Перед коммитом: `npm run build` должен проходить.

## Изображение упаковки

Единственная растровая картинка сайта. Исходник — `docs/reference/product-render.webp`,
рендер на прозрачном фоне. `npm run images` (`scripts/build-product-image.mjs`) обрезает
поля, доводит продукт до полной непрозрачности, рисует контактные тени и пишет WebP
нескольких ширин в `public/images/product/` плюс `lib/product-image.generated.ts`.
Выводит картинку `components/ui/ProductImage.tsx` — на главной с `priority` (LCP).
Сгенерированные файлы руками не правь — меняй исходник и перезапускай скрипт.

⚠️ Текущий исходник — экспорт Luma AI с водяным знаком. Не удаляй и не вырезай
водяной знак: это обход условий лицензии сервиса. Чистый файл даёт заказчик.

## Где лежат токены

Отступление от буквы ТЗ 6.1, сделанное осознанно: проект на Tailwind v4, где
конфигурация перенесена из `tailwind.config.ts` в CSS. Все токены — в блоке
`@theme` файла `app/globals.css`. Требование ТЗ по существу («токены
централизованы, произвольных hex в компонентах нет») выполняется полностью,
файла `tailwind.config.ts` в v4 просто не существует как концепции.

## Дизайн

Палитра снята с упаковки продукта: фиалковый `#6830E0` и индиго `#1030A0`
на холодном фиолетово-белом фоне `#F1EFF9`, белые поверхности, тёмный
`#171A45` как основной контраст. Скругления, много воздуха, гротеск с
хорошей кириллицей.

Зелёная гамма из ТЗ 7.2 заменена по решению заказчика: сайт и упаковка
должны читаться как один продукт. Голубой и пурпурный, которые видны на
файле развёртки, — метки реза и биговки, а не фирменные цвета.

Акцент разведён на две роли: `accent` (#6830E0) — графика и границы,
`accent-ink` (#5722C6) — ссылки и акцентный текст. В отличие от прежнего
зелёного, фиалковый проходит порог 4.5 : 1 и как текст (6.0 : 1), но у
ссылок контраст выше, и на длинных страницах это заметно.

Тёмная полоса на сайте одна — секция «Почему налёт так трудно убрать» на
главной. Это главный контраст страницы; второе такое пятно обесценит первое.

Не делай: выделения одного слова в заголовке цветом, капслок-лейблов над
секциями, одинаковых карточек для всего подряд, стрелок → в кнопках,
нумерации 01/02/03 вне раздела «Как использовать», анимаций появления
на каждой секции. Анимаций на сайте нет вовсе.

## Качество

Адаптив от 360px. WCAG 2.1 AA: контраст, видимый фокус, клавиатура,
`prefers-reduced-motion`. Lighthouse mobile ≥ 90/95/95/95.

## Команды

```
npm run dev           # разработка
npm run build         # прод-сборка + статический экспорт в out/
npm run check:content # список TODO_CONTENT (запускается автоматически перед build)
npm run typecheck     # tsc --noEmit
```

Перед сдачей: `CONTENT_STRICT=1 npm run build` — падает, если в контенте
остался хоть один `TODO_CONTENT` (критерий приёмки ТЗ 9).
