# ЭнзиДекс — сайт продукта

Полные требования: `docs/REQUIREMENTS.md`. Прочитай их перед работой над любой задачей.
Пробелы в контенте фиксируй в `docs/CONTENT-GAPS.md`.

## Продукт

Стоматологический гель «ЭнзиДекс», 10 мл, на основе фермента декстраназы.
Разрушает полисахаридный матрикс зубной биоплёнки. Без фтора.
Изготовитель: ООО «ЭНЗИДЕКС», Пермский край, РФ.

## Стек

Next.js 16 (App Router), TypeScript strict, Tailwind CSS v4, статический экспорт (`output: 'export'`).
Без UI-китов. Иконки — локальные SVG в `components/icons`. Шрифт — Onest через `next/font/google`
(файлы скачиваются на этапе сборки и раздаются со своего домена; запроса к Google в рантайме нет).

## Страницы

`/` · `/product` · `/science` · `/faq` · `/legal` · `/contacts` · `/privacy` · 404

## Жёсткие правила

1. Тексты живут в `/content/*.ts`, а не в JSX. Всегда.
2. Нет данных — ставь `TODO_CONTENT` и пиши строку в `docs/CONTENT-GAPS.md`.
   Не выдумывай факты о продукте, составе, исследованиях, реквизитах.
   Общеизвестную науку (что такое биоплёнка, что делает декстраназа, функция
   ингредиента по INCI) писать можно и нужно — это не выдумка, а справочный факт.
3. Никаких утверждений о лечебном действии. Лабораторные результаты помечаются как in vitro.
4. Одна секция = один компонент. Больше ~150 строк — разбивай.
5. Цвета только через токены, не произвольные hex в классах.
6. Секреты — только в env, никогда в коде.
7. Перед коммитом: `npm run build` должен проходить.

## Где лежат токены

Отступление от буквы ТЗ 6.1, сделанное осознанно: проект на Tailwind v4, где
конфигурация перенесена из `tailwind.config.ts` в CSS. Все токены — в блоке
`@theme` файла `app/globals.css`. Требование ТЗ по существу («токены
централизованы, произвольных hex в компонентах нет») выполняется полностью,
файла `tailwind.config.ts` в v4 просто не существует как концепции.

## Дизайн

Светлый холодный фон `#EEF3F2`, белые поверхности, тёмный `#10202A` как основной
контраст, единственный акцент `#1E7F72`. Скругления, много воздуха, гротеск с
хорошей кириллицей.

Акцент разведён на две роли: `accent` (#1E7F72) — только графика и границы,
`accent-ink` (#17655B) — текст и ссылки. Базовый акцент даёт 4.3 : 1 к фону,
чего не хватает для текста по WCAG AA; затемнённый даёт 6.1 : 1.

Не делай: выделения одного слова в заголовке цветом, капслок-лейблов над
секциями, одинаковых карточек для всего подряд, стрелок → в кнопках,
нумерации 01/02/03 вне раздела «Как использовать», анимаций появления
на каждой секции.

## Качество

Адаптив от 360px. WCAG 2.1 AA: контраст, видимый фокус, клавиатура,
`prefers-reduced-motion`. Lighthouse mobile ≥ 90/95/95/95.

## Команды

```
npm run dev           # разработка
npm run build         # прод-сборка + статический экспорт в out/
npm run check:content # список TODO_CONTENT (запускается автоматически перед build)
npm run typecheck     # tsc --noEmit
```

Перед сдачей: `CONTENT_STRICT=1 npm run build` — падает, если в контенте
остался хоть один `TODO_CONTENT` (критерий приёмки ТЗ 9).
