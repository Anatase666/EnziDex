# Пробелы в контенте

Список данных, которых нет у исполнителя и которые нельзя вывести из ТЗ.
Каждому пункту в коде соответствует маркер `TODO_CONTENT`.

Проверить текущее состояние: `npm run check:content`.
Перед сдачей: `CONTENT_STRICT=1 npm run build` — сборка падает, пока остался
хоть один пробел (критерий приёмки ТЗ 9).

Как заполнять: открыть указанный файл в `content/`, заменить `TODO_CONTENT`
на реальное значение, выполнить `npm run build`. Вёрстку править не нужно.

## Требует решения заказчика (не только данных)

### 1. Транспорт заявок — и связанный с ним вопрос 152-ФЗ ⚠️

**Где:** `.env.local` → `NEXT_PUBLIC_LEAD_TRANSPORT`, реализация в `lib/submitLead.ts`.

ТЗ FR-G3 предлагает по умолчанию вариант A — Formspree. Технически он готов
и включается одной переменной окружения. Но у него есть последствие,
которое стоит осознать до запуска: **серверы Formspree находятся за пределами
РФ**. Для оператора-резидента приём персональных данных россиян на такой
сервис — это трансграничная передача, к которой 152-ФЗ предъявляет отдельные
требования, включая локализацию баз данных на территории РФ (ст. 18 ч. 5)
и уведомление уполномоченного органа.

Заявка с сайта содержит имя, телефон и почту — это персональные данные,
исключений для «просто формы обратной связи» закон не делает.

Варианты:

| Вариант | Что делать | Риск по 152-ФЗ |
|---|---|---|
| **B (рекомендуется)** | Своя serverless-функция на российском хостинге, пересылающая заявку в Telegram. Токен бота живёт в функции, а не в браузере. Включается `NEXT_PUBLIC_LEAD_TRANSPORT=webhook` | Низкий: данные не покидают РФ |
| Российский сервис форм | Аналог Formspree с серверами в РФ | Низкий |
| A (Formspree) | Быстрее всего, но требует юридической проработки | Требует отдельного основания и уведомления |

До принятия решения транспорт стоит в режиме `console`: форма полностью
работает и валидируется, но заявка никуда не уходит, а в консоль браузера
пишется, что приём не подключён. Ни одна заявка при этом не теряется молча —
пользователь видит сообщение об ошибке с предложением написать напрямую.

**Раздел 6 политики конфиденциальности заполняется после этого выбора.**

### 2. Точная строка INCI для «монофосфата натрия» ⚠️

**Где:** `content/product.ts`, элемент с `inci: 'Sodium Phosphate'`.

В ТЗ компонент назван «монофосфат натрия». Это переведено как
`Sodium Phosphate` (натрия фосфат однозамещённый, буферный компонент).

Сверить с развёрткой упаковки обязательно, потому что по-русски название
почти совпадает с **«натрия монофторфосфат»** (`Sodium Monofluorophosphate`) —
а это источник фторида. Если на упаковке второе, то утверждение «не содержит
фтор» неверно, и с сайта придётся убрать позиционирование fluoride-free,
блок преимуществ, ответ в FAQ и строку маркировки. Цена ошибки здесь выше,
чем у любого другого пункта списка.

### 3. Регуляторный статус

**Где:** `content/legal.ts` → `regulatory`, `content/site.ts` → `footerDisclaimer`,
`content/product.ts` → `productCard.attributes`.

Категория продукции (парфюмерно-косметическая по ТР ТС 009/2011 /
медицинское изделие / иное) определяет допустимые формулировки на всём сайте.
Пока статус не подтверждён, тексты написаны по самому строгому сценарию:
никаких утверждений о лечебном действии, все лабораторные данные помечены
как in vitro.

## Что сознательно не помечено как пробел

Чтобы не было вопросов при приёмке — вот что написано без запроса к заказчику
и почему это не нарушает правило «не выдумывать факты»:

- **Механизм действия, устройство биоплёнки, роль глюкозилтрансфераз,
  номенклатура фермента (КФ 3.2.1.11).** Это опубликованная наука, каждое
  утверждение обеспечено источником из списка на `/science`.
- **Назначение каждого компонента состава.** Технологическая функция сорбитола,
  глицерина, КМЦ, ксантановой камеди, лимонной кислоты, ментола и бензоата
  натрия — справочный факт, а не характеристика этой конкретной рецептуры.
- **Свойства, следующие из состава:** отсутствие абразива и фторидов, наличие
  буферной пары, роль загустителей. Это прочитывается по списку компонентов
  и проверяется по нему же.
- **Ответы FAQ об отличиях от паст и отбеливающих средств, о том, что продукт
  не убивает бактерии и не заменяет чистку.** Следуют из механизма и состава.
- **Условия использования сайта и отказ от ответственности** (`siteTerms`).
- **Структура политики конфиденциальности** — но не её юридическая сила.
